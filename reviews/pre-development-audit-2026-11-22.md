## 8. MVP Boundary

### MVP (M1–M7) — ต้องทำจริง
- Play Alone ครบ Ch1–Ch5 + Scenario Setup + Imagined Partner + Imagined Banner
- Character creation (ลดขอบเขตตาม H-6) และ Profile Hub
- Personality Setup ทั้งฉบับสั้น (12 ข้อ) และฉบับเต็ม (36 ข้อ) + Meta options + ข้อความอิสระ + แก้ไข
- Mirror แบบคนเดียว (M01–M07, W3) + Interpretation Check + Reflection
- Comparison (กฎแบบ Solo) + Report + Next Conversation
- Export TXT/JSON/PNG + Import JSON แบบ `full`
- localStorage + Zod + ตรวจ version (ยังไม่ต้องมี migration ใด ๆ) + S18 Recovery
- Pause/Skip/Exit ทุกจุด · Safety notes · การ์ดแหล่งช่วยเหลือ · S11
- Accessibility + Responsive ตาม `06` §4
- Pixel asset แบบวาดด้วยคำสั่งบน canvas (H-5)
- **ไม่มี** Backend, LLM, Remote, Analytics เป็น dependency ✅ (ตรวจแล้ว `10` §8 สอดคล้อง)

### ย้ายออกจาก MVP ได้ (แนะนำ)
- Journey List หลายอัน + Import แบบแก้ id ชน (M-5) → Phase 2
- Observed Patterns (M-7) → Phase 2 หรือลดขอบเขต
- เสียง (M-9) → P1/Phase 2
- `RemoteAdapter` interface (M-14) → Phase 3

### Phase 2 — ยังไม่ต้องทำ
Play Together · Handoff · PIN · Reveal engine + UI Consent/Waiting · Comparison แบบ Together · Memory Scenes · Link imagined → real (M-1) · `pendingPrivateSteps` (M-2)
*Schema ควรเผื่อฟิลด์แบบ optional ไว้ตั้งแต่ M1 (`pin`, `SharedAnswer.state`) เพื่อไม่ต้อง migrate แต่ยังไม่ต้องทำ UI/logic*

### Phase 3 — ยังไม่ต้องทำ
3A Sealed Exchange · 3B Supabase (RLS, RPC, Realtime, Offline queue, Expiry) · S17 · ต้องแก้ H-1 ก่อนเริ่ม

### Architecture ที่แนะนำสำหรับ MVP (ไม่ over-engineer)

```
src/
  main.tsx, App.tsx, routes.tsx        # React Router (hash) — routes มี journeyId (CR-2)
  content/th/                          # ch1..ch5.ts, questions.ts, templates.ts, ui.ts, safety.ts
  engine/                              # pure TS ไม่มี React
    dialogue.ts                        # interpreter + conditions + tokens
    answers.ts                         # validation (meta, exclusive, maxSelect)
    compare.ts                         # categorize() + group by dimension
    report.ts                          # build + toTxt/toJson/toPng
  store/
    game.ts                            # Zustand store เดียว: save + ui state
    persist.ts                         # load (probe→parse→zod→version check) / save (debounce)
    schema.ts                          # Zod — ใช้ z.infer เป็น type หลัก
  scene/
    SceneCanvas.tsx                    # canvas 320×180, scale ด้วย CSS
    draw/                              # ฟังก์ชันวาดฉากต่อ background (คำสั่งวาดพื้นฐาน)
    sprites/                           # ข้อมูลพิกเซลตัวละครเล็ก + palette swap
    effects/                           # rain, stars, emergency light (canvas/CSS)
  ui/                                  # PixelButton, DialogueBox, ChoiceList, MetaOptions ...
  screens/                             # 1 ไฟล์ต่อหน้าจอ
```
ตัดออกจาก MVP: Remote adapter, migration framework (เก็บแค่ version check + จุดที่จะเพิ่ม migration), ตัวจัดการหลาย Journey, Observed engine (ถ้าย้ายตาม M-7)

## 10. ความพร้อมเริ่ม M1

**ยังไม่พร้อม** ด้วยเหตุผลต่อไปนี้:

1. **CR-1:** repo เป็น public และมีชื่อส่วนตัวอยู่ใน commit ที่ push แล้ว เจ้าของต้องเลือกวิธีจัดการก่อนจะ push อะไรเพิ่ม
2. **CR-2:** M1 คือการสร้าง schema และ persistence ถ้าขอบเขตข้อมูล global/Journey ยังไม่ชัด จะต้องรื้อ schema ใน M3–M6
3. **High อีก 9 ข้อ** เกือบทั้งหมดแก้ที่เอกสารอย่างเดียว ประมาณครึ่งวัน ข้อที่กระทบ M1 โดยตรงคือ H-3, H-4, H-7, H-9 (schema/persistence) ส่วน H-5, H-6 กระทบ M3–M4

**หลังแก้ CR-1, CR-2 และ High ที่เกี่ยวกับ schema (H-2, H-3, H-4, H-7, H-9) แล้ว เริ่ม M1 ได้ทันที** ส่วน H-1, H-5, H-6, H-8 แก้ก่อนถึง Milestone ที่เกี่ยวข้องก็ได้ (Phase 3, M3, M4, M3 ตามลำดับ)

### การตัดสินใจที่ต้องการจากเจ้าของ
1. CR-1: เลือกทาง (ก) Private / (ข) เขียน history ใหม่ / (ค) สร้าง repo ใหม่
2. อนุญาตให้แก้เอกสารตาม CR-2 และ High ทั้งหมดหรือไม่ (รอบนี้ยังไม่ได้แก้)
3. M-5, M-7, M-9: ยอมรับการย้ายของออกจาก MVP ตามที่แนะนำหรือไม่
4. H-1: ยอมรับให้ Remote เล่นเนื้อเรื่องแบบ Solo และแชร์เฉพาะ Mirror/Statements หรือไม่
